## Project Overview

This repository is a fork/adaptation providing **zsh tab-completion** for CLI tools. It contains two independent completion scripts:

- **`_conda`** — Zsh completion for `conda`, `mamba`, and `micromamba` package managers (the original project, forked from `conda-incubator/conda-zsh-completion`). This is a hand-written zsh completion function using the `_arguments` / `_describe` completion system.
- **`zellij.sh`** — Zsh completion for the `zellij` terminal multiplexer (~1346 lines, auto-generated by `zellij setup --generate-completion zsh`).

## Key Files

- `_conda` — The main conda completion script (compdef function `_conda`). Depends on Python for JSON parsing of conda output.
- `zellij.sh` — Zellij completion script (compdef function `_zellij`). Auto-generated, not hand-maintained.
- `conda-zsh-completion.plugin.zsh` — Oh-My-Zsh plugin loader (adds directory to `fpath`).

## Development

There is no build system, test suite, or linter. The code is pure zsh.

### Reloading completions during development

```zsh
# For _conda:
unfunction _conda && autoload -U _conda

# For zellij:
unfunction _zellij && autoload -U _zellij
```

### Zsh completion conventions

- Completion functions use `_arguments` for option/argument parsing and `_describe` for generating completion candidates.
- `_conda` uses `zstyle` for user-configurable behavior (grouping, unnamed envs, sort order).
- The `_conda` completion caches package lists via zsh's `_cache_invalid` / `_retrieve_cache` / `_store_cache` system. Cache files live in `~/.zcompcache/conda_*`.
